# 人物肖像显示设计

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-28 |
| 状态 | 已定稿（实现基线） |
| 范围 | 人脉 / 恋人肖像；玩家与 AI 头像预留 |

## 目标

让关系人「有脸」，提升约会、好友、结识与结算的代入感。先接入 5 张真图，目录可扩到 20+；无图时统一 placeholder，布局与有图一致。

## 决策摘要

| 项 | 决定 |
|---|---|
| 对象 | 仅 `Relation`（人脉/恋人）；玩家/AI 本轮不渲染 |
| 素材 | 真图；现有 5 张 → `web/public/portraits/g01.png`…`g05.png`；后续再加 15 张 |
| 分配 | 每张图全局独占（`portraitId`）；新建关系时从未占用池抽取；池空则无 id → placeholder |
| 无图 | 色块 + 名字首字，占位尺寸与真图档位一致 |
| 本轮真图 UI | A 好友详情 · B 约会选人 · C 约会选场所 · F 好友列表 · G 事件结识遇见 · H 终局结算恋人 |
| 本轮不做真图 UI | D 事务所 · E 店铺编制（保持文字列表；以后接同一 `Portrait`） |

## 数据

- `Relation.portraitId?: string`
- 新建路径（`meet` 效果、事务所推荐、空地雇佣等走 `makeRelation` 的入口）在写入前调用 `pickPortraitId(used, rng)`
- 挖角 `transferRelation`：保留原 `portraitId`
- 旧档无字段：留空 → placeholder（不做强制回填）

## 资源与解析

- 文件：`/portraits/{id}.png`（Vite `public`）
- `web/src/game/portraits.ts`：
  - `PORTRAIT_CATALOG`：已登记 id 列表（先 5 个）
  - `usedPortraitIds(players)` / `pickPortraitId(used, rng)`
  - `portraitUrl(id)`：有登记返回 `/portraits/{id}.png`，否则 `null`
- UI 不硬编码路径；加图 = 加文件 + 目录一行

## UI 组件

- `web/src/ui/components/Portrait.tsx`（+ css）
- props：`name`、`portraitId?`、`size: 'sm' | 'md' | 'lg'`
- 纯展示；禁止改现金/关系

### 尺寸用途

| size | 用途 |
|---|---|
| sm | 好友列表行 |
| md | 约会选人卡片 |
| lg | 好友详情、结识遇见、结算恋人 |

## 展示位（本轮）

1. **好友列表**：行首 `sm`
2. **好友详情**：标题旁/上方 `lg`
3. **约会选人**：按钮内 `md` + 文案
4. **约会选场所**：标题区显示已选对象 `md`/`lg`
5. **结识遇见**：人类玩家在 `meet` 产生新关系后弹层「遇见 {name}」+ `lg`，确认后关闭（UI 本地状态即可；不阻断存档结构）
6. **终局结算**：人类最高好感未破裂恋人（无则最高人脉）展示 `lg`；无关系则跳过图

## 明确不做（本轮）

- 事务所 / 店铺编制接肖像
- 玩家与 AI 棋子头像
- 立绘情绪差分、好感驱动换装
- 成人/露骨构图

## 其他 UI 建议（非本轮必做）

| 建议 | 为何 | 优先级 |
|---|---|---|
| 关系破裂时头像灰阶 + 「已疏远」角标 | 强化维护压力 | P1 |
| 约会确认瞬间短闪光/好感 +N 飘字 | 反馈更爽 | P1 |
| TopBar 旁「最近维护对象」小头像 | 提醒衰减 | P2 |
| 拉霸事件卡若涉及具体关系人时带小头 | 事件有人味 | P2 |
| 结算三人高光（资产/人脉/恋人代表图） | 故事收束 | P2 |

## 测试

- `portraits.test.ts`：占用池抽取、池空返回 undefined、url 解析
- 新建 `meet` 关系带上未占用 `portraitId`（reduce / 现有 meet 相关测可扩一条）
- UI 以手工 / 现有 e2e 冒烟为主（肖像不挡流程）
