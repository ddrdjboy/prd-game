# 兴趣爱好与投其所好送礼

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-26 |
| 状态 | 设计已定，待实现 |
| 关联 | 人际关系好感、商店落点、约会 |

## 目标

- 每人有独立兴趣属性（非挂在名字上），结识时不同
- 商店送礼先选礼再选人；投其所好加分更高
- 好感去掉上限 100

## 数据

### Relation

```ts
hobbies: string[]  // 1–3 个 hobbyId
```

### 兴趣池（≥20）

见实现文件 `web/src/game/hobbies.ts`，示例类别：酒、花、茶、咖啡、美食、甜品、运动、健身、球类、数码、游戏、摄影、阅读、写作、音乐、电影、旅行、户外、宠物、手作、收藏、时尚、美妆、车、棋牌、综艺 等（实现时凑满 ≥20，带中文名）。

### 初始与再开

| 时机 | 规则 |
|------|------|
| 结识 / `__hire__` / 事务所推荐 | 从池中随机 **1** 个，写入 `hobbies` |
| 约会成功 | 若 `<3`，约 **25%** 再抽 1 个未拥有兴趣 |
| 好感首次 ≥60 / 首次 ≥90 | 各一次；若 `<3`，约 **35%** 再开；用 `hobbyMilestones: number[]` 记录已触发阈值，旧档默认 `[]` |
| 旧存档缺 `hobbies` | 补 1 个随机 |

不按人名写死兴趣；局内名字不重复，每人属性独立即可。

## 好感上限

- 移除所有 `Math.min(100, score + …)`（meet / boost / 约会 / 公园 / 事务所 / 挖角挽留等）
- 下限仍 `Math.max(0, …)`
- 店铺 CF 仍用 `relationMultiplier = 0.5 + score/200`，不另设分数硬顶

## 商店送礼（方案 1）

### 礼物表

- 扩展 `SHOP_ITEMS`：多件礼物，每件带 `hobbyId` + `baseBoost`（沿用约 12 量级，可随价微调）
- 旧「精致礼物 / 好酒礼盒」并入带标签礼物（不再按 romance/network 硬分流）
- 礼物种类约 **8～12**，兴趣 ≥20：多兴趣可共享同一礼物标签（匹配看 `hobbies.includes(gift.hobbyId)`）

### 流程

1. 落点商店：选礼物（扣现金）
2. 再选一名 `status !== 'broken'` 的关系人
3. 计算加分：
   - **匹配**：`baseBoost × 2`
   - **不匹配**：`baseBoost × U(0.5, 1)`（实现可用 `0.5 + rng()*0.5`）
4. 日志：`送给「名」·投其所好/兴趣不合 · 好感+N`
5. 动作建议：`LOCATION_BUY_GIFT { itemId, relationId }`（或两步：选礼暂存 pending，再确认对象；优先单动作避免半截状态）

非礼物类商店货（课程、数码等）保持原逻辑，不选手。

### UI

- 商店：礼物 → 选人列表（展示对方兴趣标签，便于投其所好）
- 好友详情：只读显示兴趣；**不**在此送礼

## AI

- 优先选「至少一名关系人 hobbies 匹配」的礼物，送给匹配者中好感较低者
- 否则买任意可负担礼物，送给好感最低者

## 验收

- 结识后必有 1 个兴趣；同局多人兴趣可不同
- 送礼匹配为 2×、不匹配在 0.5～1×
- 好感可超过 100
- 约会/跨阈值可再开兴趣且 ≤3
- 旧档迁移有 hobbies
