# 约会功能设计规格

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-25 |
| 状态 | 已定稿（实现基线） |
| 深度 | 轻量增强：选人 + 选场所，一次结算 |

## 目标

行动点入口 **「约会·交友」**：选对象（恋人 **或** 人脉）→ 选场所 → 扣费加好感。纯正向，无翻车。

已移除独立「维护人脉」行动；人脉升温并入本流程。

## 流程

1. 点「约会·交友」：不扣 AP；若无可选对象 → 日志提示并返回。
2. `pendingDate.step = pickPartner`：列出可约恋人与人脉。
3. 选中对象 → `step = pickVenue` + `relationId`。
4. 选场所：现金不足禁用；确认后扣 1 AP + 花费，对该人加固定好感，写日志，清 pending。
5. 「算了」：取消，不扣 AP。

## 可选对象

- 恋人：`dating` / `engaged` / `married`
- 人脉：`new` / `stable` / `partner`

## 场所（万）

| id | 名称 | 花费 | 好感 | 说明 |
|---|---|---|---|---|
| park | 公园散步 | 0.05 | +6 | 轻松 |
| cafe | 咖啡厅 | 0.12 | +9 | 闲聊 |
| cinema | 电影院 | 0.20 | +12 | 观影 |
| dinner | 餐厅正餐 | 0.35 | +16 | 正餐 |
| surprise | 惊喜安排 | 0.55 | +22 | 用心安排 |

特质加成：恋约 +`romanceBoost`(+4)；交友 +`networkBoost`(+4)。

## 数据

- `PendingDate`: `{ playerId, step, relationId? }`
- 动作：`DATE_PICK_PARTNER` / `DATE_CONFIRM_VENUE` / `DATE_CANCEL`
- `SPEND_ACTION`：仅 `date`（店铺改为只读浏览，不耗行动点）

## 明确不做

- 独立「维护人脉」按钮
- 多步剧情、随机翻车、约会专属事件牌
